# نمای کلی پروژه

## ۱. مسئله

بازار خودروی ایران اطلاعات پراکنده دارد: قیمت در شبکه‌های اجتماعی، مشخصات در سایت‌های متفرقه و تاریخچه تقریباً هیچ‌جا. «لامرد خودرو» یک مرجع فارسی برای سه پرسش است:

1. قیمت امروز یک خودرو چقدر است و نسبت به روز قبل چه تغییری کرده؟
2. مشخصات فنی و نسخه‌های یک مدل چیست؟
3. دو تا چهار خودرو در کنار هم چه تفاوتی دارند؟

## ۲. مخاطب و مسیرهای اصلی

| مخاطب | مسیر | نتیجه |
| --- | --- | --- |
| خریدار | صفحه اصلی ← قیمت روز ← جزئیات خودرو | قیمت به‌روز + روند تاریخی + تماس |
| مقایسه‌گر | مقایسه ← انتخاب ۲ تا ۴ خودرو | جدول مقایسه قیمت و مشخصات |
| پژوهشگر بازار | گزارش‌ها / بیشترین تغییرات | فهرست رشد و کاهش قیمت |
| مدیر | پنل «مدیریت قیمت خودرو» | دریافت، اعتبارسنجی، خروجی، تنظیمات |

## ۳. دامنه

در دامنه:

- قیمت روز، تاریخچه، برند، مقایسه، بانک اطلاعات خودرو، اخبار، جستجو
- آگهی‌های فروش با درج از پنل مدیریت، فروش ویژه تایمردار و صفحه عمومی آگهی
- هشت زیرمنوی مدیریت، خروجی Excel/CSV/PDF، همگام‌سازی زمان‌بندی‌شده
- REST خواندنی برای مصرف بیرونی

خارج از دامنه (عمداً):

- ثبت‌نام کاربر، سبد خرید، پرداخت، پیام خصوصی، ثبت آگهی از سمت کاربر
- درج خودکار آگهی یا قیمت از منابع متفرقه
- داده نمایشی/ساختگی برای پر کردن نمودار

## ۴. معماری در یک نگاه

```
مرورگر
  │  HTML / CSS / JS (بدون فریم‌ورک)
  ▼
قالب lamerd-khodro        نمایش، فیلتر AJAX، نمودار، مقایسه
  │  فقط توابع lk_* (قرارداد پایدار)
  ▼
افزونه Core               CPT، تاکسونومی، Query، Registry، REST، JSON-LD
  │  LK_Price_Repository (اینترفیس) ← LKPE_Repository
  ▼
افزونه Price Engine       دریافت، اعتبارسنجی، تاریخچه، گزارش، خروجی
  │  HTTPS با Rate limit و Retry
  ▼
منبع بیرونی (کافه خودرو)  فقط خواندن؛ خروجی این مسیر در MySQL ذخیره می‌شود
```

قواعد کلیدی این مرزها:

- قالب بدون افزونه هسته همچنان بارگذاری می‌شود (توابع با `function_exists` محافظت شده‌اند) و در نبود داده، حالت خالی صادقانه نشان می‌دهد.
- موتور قیمت می‌تواند بدون قالب اجرا شود؛ همه ورودی‌ها از CRON و پنل مدیریت می‌آیند.
- Core هیچ‌گاه به API بیرونی وصل نمی‌شود و Price Engine هیچ‌گاه HTML رندر نمی‌کند.

## ۵. جریان داده قیمت

1. **دریافت** (`LKPE_Source`): صفحه فهرست قیمت‌ها خوانده و به رکوردهای خام تبدیل می‌شود؛ هر درخواست با محدودیت ۱۲۰/دقیقه و بازآزمایی نمایی برای 429/5xx/Timeout.
2. **نگاشت** (`LKPE_Vehicles` + `LKPE_Brand_Resolver`): شناسه منبع ← خودروی داخلی؛ برند از گروه منبع یا تشخیص واژگانی استخراج و در تاکسونومی `lk_brand` تطبیق داده می‌شود (بدون تکرار).
3. **اعتبارسنجی** (`LKPE_Validator`): قیمت نامعتبر یا صفر → `null`؛ جهش غیرمنطقی → رکورد `suspect` که در تاریخچه ذخیره می‌شود ولی در نمایش عمومی کنار گذاشته می‌شود.
4. **ذخیره** (`LKPE_Repository`): درج قیمت جدید، ثبت تاریخچه روزانه، به‌روزرسانی نمای تجمیعی خودرو، snapshot برای گزارش.
5. **نمایش**: قالب از `lk_get_price()` و تاریخچه تجمیع‌شده روزانه می‌خواند؛ نمودار اگر داده کافی نباشد پیام «داده کافی نیست» نشان می‌دهد.

## ۶. قواعد نمایش داده

- `null` به معنی «قیمت ثبت نشده» است و هرگز با `0` یا «تماس بگیرید» جایگزین نمی‌شود.
- تاریخچه فقط از زمان راه‌اندازی این نصب وجود دارد؛ هیچ بازسازی گذشته‌ای انجام نمی‌شود.
- هر صفحه قیمت، نام و لینک منبع را نشان می‌دهد.
- درصد تغییر فقط وقتی محاسبه می‌شود که قیمت مبنا موجود باشد؛ در غیر این صورت «—».

## ۷. وضعیت فعلی نصب

- ۱۱۵ خودرو، ۹۹ خودرو با قیمت جاری، ۱۶ خودرو بدون قیمت ثبت‌شده
- ۱۱۰ رکورد تاریخچه و ۱۱۵ snapshot
- پس از دریافت بامدادی، منبع برای همه خودروها تغییر «۰» برمی‌گرداند؛ بنابراین نبض بازار ۰ افزایش / ۰ کاهش / ۹۹ بدون تغییر است و بخش «بیشترین تغییرات» تا دریافت روز بعد رندر نمی‌شود. این رفتار عمدی و صادقانه است، نه خطا.
- نمودار تک‌خودرو در نصب تازه «داده کافی نیست» است، چون تاریخچه یک‌روزه است؛ این رفتار مورد انتظار است.
