# معماری پروژه لامرد خودرو

> نسخه ۱.۰ — فاز اول (وب‌سایت). این سند مرجع تصمیم‌های معماری است و همراه با کد به‌روزرسانی می‌شود.

## ۱. اصل حاکم

منطق کسب‌وکار در قالب نیست. اطلاعات خودرو، قیمت، تاریخچه، گزارش و API در افزونه‌ها زندگی می‌کنند و قالب فقط لایه نمایش است. با تغییر یا حذف قالب، هیچ داده‌ای از دست نمی‌رود.

```
┌──────────────────────────────────────────────────────────────┐
│                        WordPress Core                        │
│                    MySQL (پیشوند: ouskhodro_)                │
└───────────────┬───────────────────────────┬──────────────────┘
                │                           │
     ┌──────────▼───────────┐    ┌──────────▼─────────────────┐
     │ lamerd-khodro-core   │    │ lamerd-khodro-price-engine │
     │ (دامنه خودرو)        │◄───┤ (دریافت، ذخیره، تحلیل)     │
     │ CPT, Taxonomy, Meta  │    │ Provider, Sync, History,   │
     │ REST /lamerd/v1      │    │ Reports, Export, Cron      │
     │ Registry + Null Repo │    │ ثبت Repository در Registry │
     └──────────┬───────────┘    └────────────────────────────┘
                │  API عمومی (lk_*)
     ┌──────────▼───────────┐
     │   lamerd-khodro      │
     │   (قالب اختصاصی)     │
     │   HTML/CSS/JS فقط    │
     └──────────────────────┘
```

## ۲. اصول وابستگی

| لایه | اجازه دارد از | نباید از |
|---|---|---|
| قالب | توابع عمومی `lk_*` در Core | کلاس‌های داخلی افزونه‌ها، جداول DB، API خارجی |
| Core | WordPress، Registry | Price Engine به‌صورت مستقیم (فقط از طریق Registry) |
| Price Engine | WordPress، Core (CPT، فرمت‌دهی) | قالب، خروجی HTML عمومی |

Core فقط از یک قرارداد (interface) برای قیمت‌ها آگاه است. Price Engine پیاده‌سازی واقعی را در `LK_Registry` ثبت می‌کند. اگر Price Engine غیرفعال باشد، `LK_Null_Price_Repository` بارگذاری می‌شود و سایت بدون خطای مرگبار و با پیام «قیمت در دسترس نیست» کار می‌کند.

### قرارداد `LK_Price_Repository_Interface`

```php
get_vehicle_price( int $post_id ): ?array
get_prices( array $args ): array{ items, total, pages, page }
get_history( int $post_id, string $from, string $to ): array
get_change_stats(): array{ total, up, down, flat, no_price }
get_last_sync(): ?array
get_top_movers( string $dir, int $limit ): array
```

شکل خروجی قیمت:

```php
[
  'market_price'     => ?int,     // تومان، null یعنی «ناموجود» (هرگز صفر)
  'factory_price'    => ?int,
  'change_amount'    => ?int,
  'change_percent'   => ?float,
  'fetched_at'       => 'Y-m-d H:i:s',
  'fetched_ts'       => int,      // timestamp محلی وردپرس
  'declared_at'      => ?string,  // زمان اعلام منبع (متفاوت از زمان دریافت)
  'data_status'      => 'valid|incomplete|suspect',
  'is_stale'         => bool,     // کهنه بودن نسبت به بازه همگام‌سازی
  'source'           => 'cafekhodro',
  'previous_market'  => ?int,
]
```

## ۳. ثبت و بارگذاری

- ترتیب بارگذاری: Core → Price Engine → Theme.
- Price Engine در `plugins_loaded` بررسی می‌کند `class LK_Registry` وجود دارد؛ در غیر این صورت در پیشخوان اعلان وابستگی نمایش می‌دهد و بارگذاری سنگین را متوقف می‌کند.
- نسخه‌ها با `LK_VERSION` / `LKPE_VERSION` و asset versioning مدیریت می‌شوند.
- همه فایل‌ها با `ABSPATH` guard و prefix یکتا (`LK_`, `LKPE_`, `lk_`, `lkpe_`) نوشته شده‌اند.

## ۴. چرخه داده قیمت

```
CafeKhodro API ──► Provider (HTTP + Retry + RateLimit)
                        │
                   Normalize + Validate
                        │
                 Upsert لایه خودرو (lkp_vehicles) ──► CPT lk_vehicle
                        │
             مقایسه با آخرین قیمت معتبر
                        │
        ┌───────────────┴────────────────┐
   بدون تغییر                       تغییر قیمت
   فقط fetched_at                   رکورد history (جداگانه برای کارخانه/بازار)
        │                                 │
        └──────────► lkp_current_prices ◄─┘
                              │
                    نمایش / نمودار / گزارش
```

هیچ صفحه عمومی در زمان درخواست به API خارجی وصل نمی‌شود. تنها مسیر تماس با API، عملیات همگام‌سازی مدیریتی یا Cron است.

## ۵. آماده‌بودن برای اپلیکیشن

- REST اختصاصی `lamerd/v1` با نسخه در مسیر، صفحه‌بندی، فیلتر و سقف `per_page`.
- خروجی JSON استاندارد با ساختار ثابت و `meta` صفحه‌بندی.
- Rate limit سبک بر پایه IP برای مسیرهای عمومی.
- لایه داده مستقل از قالب، قابل استفاده در اپ اندروید/iOS.
- احراز هویت آینده از طریق `application password` وردپرس یا OAuth افزودنی، بدون تغییر قراردادها.

## ۶. تصمیم‌های ثبت‌شده

1. **CPT + جدول موازی:** CPT `lk_vehicle` مالک محتوای تحریریه و مشخصات است؛ جدول `lkp_vehicles` مالک نگاشت منبع و شناسه بیرونی. اتصال با `post_id`.
2. **`null` ≠ `0`:** قیمت ناموجود در همه لایه‌ها `NULL` است؛ در نمایش «ناموجود» و در مقایسه/میانگین کنار گذاشته می‌شود.
3. **تاریخچه فقط از زمان راه‌اندازی:** هیچ داده تاریخی ساختگی تولید نمی‌شود؛ نمودار با پیام «داده کافی نیست» شروع می‌شود.
4. **اعتبارسنجی منبع:** تغییر قیمت ناسازگار (درصد خارج از بازه ۱۰۰± یا بزرگ‌تر از دو برابر قیمت) با وضعیت `suspect` ذخیره می‌شود، قیمت‌ها حفظ می‌شوند و مقدار تغییر نمایش داده نمی‌شود. نمونه واقعی: خودروی ۹۴ با تغییر ۹۹.۹- درصد.
5. **بدون صفحه‌ساز:** همه قالب‌ها PHP دست‌نویس با CSS Variables و Logical Properties.
6. **خروجی PDF:** صفحه گزارش چاپ‌بهینه راست‌چین با `@page` و فراخوانی چاپ مرورگر؛ بدون وابستگی کتابخانه سنگین PDF.
7. **XLSX:** نویسنده سبک بر پایه `ZipArchive` (افزونه zip فعال است)، اعداد واقعی سلولی و `rightToLeft="1"`.
8. **فونت:** وزیرمتن به‌صورت woff2 محلی در قالب، بدون درخواست به دامنه خارجی.
